# PosePro AI Camera V2.1 移动端交互 Demo

这是在原有 MusePilot HTML 原型上调整的 **PosePro V2.1 可交互体验**，结合 [PRD V2.1](../PosePro_AI_Camera_PRD_V2.1.md)、[人像摄影规则库](../PosePro_Portrait_Photography_Rules_V1.0.md)和本轮讨论。界面使用英语，面向成年单人人像；重点是低门槛的拍摄参考与拍摄者协作。

本原型用于审阅流程、内容和状态。它没有接入实时姿态识别、云端大模型、图像生成服务或生产级 LUT 调色。文档中的目标能力不代表已经实现的算法。

下一阶段需求已更新为 [PRD V2.2](../PosePro_AI_Camera_PRD_V2.2.md)，聚焦旅行与日常朋友帮拍、完整免费首拍和效果验证。本 HTML 仍为上述 V2.1 交互原型，未迁移至 V2.2，不作为其原生指导、内容复拍或商店交易的完成证据。

## 打开方式

双击根目录 [PosePro_Demo.html](../PosePro_Demo.html)。CSS、JavaScript、图标和四张 WebP 样例均已内嵌，无需安装依赖，可离线体验样例流程。[PosePro_Demo.zip](../PosePro_Demo.zip) 包含同一单文件和源代码。

源代码入口为本目录 [index.html](index.html)，打开时应保留同目录 CSS、JS 和 `assets`。`MusePilot_Demo.html` 与 `MusePilot_Demo.zip` 是同步生成的兼容文件名，内容与新交付一致。

真实摄像头需要浏览器支持、安全上下文与用户授权。推荐通过本地服务或 HTTPS 访问，并主动选择 **Use my camera**：

```powershell
python -m http.server 4173 --bind 127.0.0.1 --directory demo
```

浏览器打开 `http://127.0.0.1:4173`。直接打开本地文件时，浏览器可能不提供摄像头接口；可继续使用样例。

## 两分钟体验路径

1. 打开后直接进入 **Camera**，默认是标明来源的 AI 样例，没有自动申请相机权限。
2. 选择 **I'm in Frame / I'm Shooting**，再按实际需要选择前后镜头与手持/固定支撑。角色、镜头和支撑相互独立。
3. 在 **Templates** 浏览场景与模板。免费提供三套基础 AI 模板，其余模板展示 Pro 锁定状态；真人摄影师合集标为 **Coming soon**，没有用 AI 样例冒充实拍。
4. 回到 Camera，手动查看 **Frame / Camera / Pose / Expression** 提示，切换三个姿势参考，体验暂停和无法判断状态。提示不是检测结论，不要求先完成提示才允许拍摄。
5. 使用快门与倒计时，进入照片结果。默认 **Original**，可自行选择预设、强度及曝光/对比度/色温的视觉示例，再决定重拍、保存记录或下载照片。
6. 在 **Me** 查看记录、收藏和设置；体验月付/年付模拟订阅及恢复。价格为 **$4.99/月、$34.99/年**，两个档位均展示 **7 天模拟试用**，没有真实交易。

## 业务与体验规则

| 事项 | 本版实际规则 |
| --- | --- |
| 导航 | Camera / Templates / Me 三个 Tab。Camera 是首屏；设置从 Me 进入。 |
| 指导 | 每次显示一条人工可审阅的参考提示，由用户手动切换。暂停、无法判断或未完成提示不锁快门。 |
| 人体轮廓 | 视觉参考；不执行 MediaPipe、Apple Vision 或 ARKit，不代表已经跟踪到用户身体。 |
| 模板来源 | 四张既有 AI 生成人像作为样例素材；来源与 Free/Pro 权益分别标示。职业摄影师素材尚未接入。 |
| 参考资产 | 复用 Café / Outfit / Travel / Window light 四张成年单人 WebP。多个模板可能复用同一示例图，不代表已有完整摄影素材库。 |
| 拍摄角色 | 入镜者/拍摄者角色独立于前后镜头，也独立于手持/固定手机。方向提示使用明确的画面或执行者语境。 |
| 调色 | 默认 Original；预设需用户主动选择。CSS 预览与 canvas 导出用于视觉示例，没有真实 3D LUT、局部分区调色、五官或身形改造。 |
| 订阅 | 仅改变当前浏览器的演示权益。未连接 StoreKit、Stripe、真实账单或试用资格校验；不宣称能恢复实际商店购买。 |
| 推荐模型 | 本版不调用任何推荐模型。内容生产端生成图片/关键点/文案与手机端实时感知，是后续分开的工作。 |

## 数据与浏览器边界

| 能力 | 行为与限制 |
| --- | --- |
| 元数据记录 | 使用浏览器 localStorage 保存模板标识、时间、选择、收藏及演示权益等元数据；样例路径可随元数据保存。照片字节不写入 localStorage。 |
| 真实摄像头 | 只有用户明确选择时才请求 `getUserMedia`；预览和捕获在本页面处理。相机失败后可重试或回到样例。前后镜头选择受浏览器与实际设备支持限制。 |
| 真实照片 | 捕获图像仅用于当前页面内存中的预览/导出。刷新或关闭页面后，元数据记录不能恢复真实照片字节。 |
| 下载 | 请求浏览器下载图片；文件去向和 iPhone 上的打开/保存行为由系统与浏览器决定。网页不能直接写入系统 Photos，也没有使用 PhotoKit。 |
| 分享 | 浏览器和设备支持能力可能不同；下载是可用的交付途径，不承诺系统相册或分享面板行为一致。 |
| 隐私 | 本版不上传相机帧、照片或人体关键点；没有埋点、广告 SDK 或服务器端账号。用户自行下载后的文件由用户管理。 |
| 持久化 | 浏览器清除数据、隐私模式、禁用存储或 `file://` 的实现差异会影响记录；同一文件换位置打开也可能得到不同存储空间。 |

## 页面和边界状态

覆盖 Camera、模板筛选与权益、拍摄参考、暂停/无法判断、倒计时、照片编辑与结果、Me、记录与收藏、设置、隐私、模拟订阅与恢复。

保留用户可理解的空列表、加载反馈、相机拒绝/不可用、倒计时取消、记录失败和删除确认。演示控制用于审阅状态，不表示运行了相应的识别算法。拍摄过程中手动快门始终是用户的选择。

## 移动端布局

沿用原型的系统字体回退、安全区、内层滚动、44px 最小触控目标、浮动导航和模糊面板。桌面保留设备外壳与体验导览；移动端显示应用本身。提供 Light / Dark / System 外观与减少动态效果支持。

网页通过 CSS 近似 iOS 视觉，不能据此声称完成 SwiftUI 原生组件或 Apple HIG 全面验收。

### 2026-11-01 · UI UX PRO MAX 界面优化

本轮使用 **UI UX PRO MAX** 的简洁工具界面、触控间距、可读文字与焦点可见性指导，保留相机优先的产品流程和现有暖白、深绿色调：

- **Camera**：减少取景区常驻控件，把次要操作放入工具面板；保持快门、暂停和当前一句提示容易找到。
- **Templates**：改善卡片标题、AI 来源、Pro 权益和收藏按钮的层级与间距，不把来源和权益混为同一分类。
- **Photo**：优先展示完整照片，清楚区分原图对比、预设选择、滑条与主要保存动作。
- **Me 与弹层**：统一列表、按钮、标题和说明文字，减少视觉拥挤；浅色与深色主题使用配套语义色。
- **移动端**：提高小字号的可读性，保留安全区、可见键盘焦点、减少动态效果与适合触屏的操作区域。

使用本地系统字体、原有 SVG 图标与四张样例图，没有引入字体 CDN、运行时第三方组件或额外网络资源。

## 源码与打包

```text
demo/
  index.html        页面外壳与桌面导览
  styles.css        既有组件、响应式布局与动画
  ui-refinement.css 共享视觉 Token、相机和导航优化
  ui-pages.css      模板、个人中心、编辑和弹层优化
  app.js            页面、交互、权限、计时与照片视觉处理
  model.js          模板、元数据、本地权益与记录
  assets/           四张 AI 样例 WebP 与图标
  build_demo.py     标准库单文件内嵌与 ZIP 打包
```

重新构建交付文件：

```powershell
python demo/build_demo.py
```

生成 `PosePro_Demo.html`、`PosePro_Demo.zip`，同时同步旧名称兼容副本。ZIP 包含当前源文件、交付说明、参考 PRD/摄影规则与所需素材；不包含旧 `qa/` 结果、旧 `model.test.cjs` 或原始 PNG。四图内嵌在 UI 资产映射中，元数据记录仍保存资产路径，不复制图像内容。
